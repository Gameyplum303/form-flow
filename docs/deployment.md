# Deployment

FormFlow's public demo runs on [Render](https://render.com)'s free plan, described by [`render.yaml`](../render.yaml) at the repository root (a Render Blueprint). It creates three services:

| Service | What it runs | Address |
|---|---|---|
| `gameyplum-formflow-api` | The API from `FormFlow.Backend/Dockerfile`, with Swagger UI | https://gameyplum-formflow-api.onrender.com/swagger |
| `gameyplum-formflow` | The Blazor app from `FormFlow.Blazor/Dockerfile` | https://gameyplum-formflow.onrender.com |
| `gameyplum-formflow-react` | The React app, built as a static site | https://gameyplum-formflow-react.onrender.com |

## Deploy it

1. Sign in to [Render](https://dashboard.render.com) with GitHub. The free plan needs no card.
2. Choose **New > Blueprint**, pick this repository, and select **Apply**. Render builds the three services, which takes several minutes the first time.
3. Check that the addresses Render shows match the table above. Render adds a suffix when a name is taken. If it did, change the URLs in `render.yaml` to match, then push: they are the Blazor app's `BackendApi__BaseUrl`, the API's `Email__LinkBaseUrl`, and `REACT_APP_API_URL` in the React build command.

After that, each push to `main` redeploys the services whose folders changed, once the GitHub checks pass.

## What the demo is like

- **It starts fresh.** The free plan has no disk, so LiteDB lives inside the container. Each restart or redeploy brings back the demo survey with 80 made-up responses from the last three weeks (`SeedData__SampleResponses`), and the two demo accounts. Anything visitors add disappears then too.
- **Anyone can sign in.** The accounts are `admin` / `password` (administrator) and `professor` / `password`, and the sign-in page says so. That's safe only because nothing in the demo is private and it resets itself. For a real deployment, remove those `Accounts__*` settings and add your own accounts with real passwords.
- **It sleeps.** A free service stops after 15 minutes without visits, and the next visit waits about a minute while it starts. Open the Blazor app a minute before showing it to someone.
- **Emails aren't sent.** Verification and reset emails appear on the administrator's **Emails** page. To send real ones, add the `Email__Smtp__*` settings to the API service ([backend.md](backend.md#configuration)).

## How the settings fit together

- `PORT=8080` tells Render which port the containers listen on (the images set `ASPNETCORE_HTTP_PORTS=8080`).
- `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` makes ASP.NET Core use the `X-Forwarded-For` and `X-Forwarded-Proto` headers from Render's proxy. The API's rate limits then count each visitor's address instead of the proxy's, and the Blazor app builds share links with `https`.
- `Jwt__Key` is generated by Render when the Blueprint is created, so it stays the same across deploys.
- The React app calls the API from the browser, so the API address is compiled into it at build time. The Blazor app calls the API from its server.

To run the same containers on another host, use the Dockerfiles with the settings above; `docker-compose.yml` shows the local version.
